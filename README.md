# Rust 2FA · 终端验证码工具

[English](README.en.md) | 简体中文

一个使用 Rust 编写的 TOTP（基于时间的一次性密码）生成器，搭配 Ratatui 终端界面。输入 Base32 密钥后，即可查看当前六位验证码、剩余有效时间和刷新进度。

> 本项目是单账户、本地运行的学习型工具，不是加密密钥保险库。请先使用测试密钥验证功能，再决定是否用于真实账户。

## 功能

- **隐藏输入密钥**：启动后交互输入，不需要将密钥放在命令行参数中。
- **自动规范化输入**：忽略空格、换行等空白字符，将小写转换为大写，并去除 `=` 填充符。
- **六位验证码**：保留前导零，以 `123 456` 的形式分组显示。
- **自动刷新**：每 30 秒切换验证码；界面约每 100 毫秒检查事件并刷新。
- **有效期进度条**：显示当前验证码的剩余有效时间。
- **动态状态颜色**：绿色表示有效，黄色提示尽快使用，红色表示即将刷新。
- **深色终端界面**：居中圆角卡片，随终端尺寸调整布局。
- **快捷退出**：按 `q`、`Q` 或 `Esc` 退出并恢复终端状态。

## 安装与运行

需要安装 Rust 和 Cargo，并在交互式终端中运行。推荐使用 Windows Terminal 或其他支持 Unicode 和真彩色的现代终端。窗口至少约 64 列、21 行时，可以完整展示卡片。

在项目根目录执行：

```bash
cargo run
```

出现提示后，输入或粘贴服务提供的 **Base32 TOTP 密钥**，然后按 Enter：

```text
请输入 Base32 密钥:
```

输入内容不会回显。这里需要的是开启双因素认证时提供的密钥，**不是账户登录密码，也不是当前的六位验证码**。

密钥可以包含空格或使用小写。例如以下输入会被规范化为相同的内容：

```text
JBSWY3DPEHPK3PXP
jbswy3dpehpk3pxp
jbsw y3dp ehpk 3pxp
```

> 上述密钥仅用于演示，公开示例密钥不能保护真实账户。

### 编译后直接运行

```bash
cargo build --release
```

Windows PowerShell：

```powershell
.\target\release\rust_2fa.exe
```

Linux / macOS：

```bash
./target/release/rust_2fa
```

可执行文件名取决于 `Cargo.toml` 中的包名或二进制目标名；以上以 `rust_2fa` 为例。

## 界面说明

| 区域 | 内容 |
| --- | --- |
| 标题 | Rust TOTP 和双因素认证说明 |
| 当前状态 | 验证码有效、请尽快使用或即将刷新 |
| Current Code | 当前六位验证码，以两组三位数字显示 |
| Validity | 剩余秒数与有效期进度条 |
| 底部提示 | 自动刷新说明、安全提示和退出快捷键 |

| 剩余时间 | 颜色 | 状态 |
| --- | --- | --- |
| 11–30 秒 | 绿色 | 验证码有效 |
| 6–10 秒 | 黄色 | 请尽快使用 |
| 1–5 秒 | 红色 | 即将刷新 |

进度条显示的是**当前时间窗口剩余的比例**，不是程序运行进度。

## 项目结构

| 文件 | 职责 |
| --- | --- |
| `Cargo.toml` | 包信息与依赖配置 |
| `Cargo.lock` | 锁定依赖版本，便于复现构建 |
| `src/main.rs` | 模块声明、隐藏读取密钥、处理错误并启动界面 |
| `src/totp.rs` | Base32 解码、TOTP 计算和剩余时间计算 |
| `src/ui.rs` | 主题、卡片布局、进度条、状态颜色和键盘事件 |

## 技术实现

当前实现使用以下固定参数：

| 参数 | 值 |
| --- | --- |
| 算法 | HMAC-SHA1 |
| 时间步长 | 30 秒 |
| 验证码位数 | 6 位 |
| 时间起点 | Unix Epoch |
| 密钥编码 | Base32 |

程序将 Unix 时间戳除以 30 得到计数器，将计数器编码为八字节大端数据，然后使用解码后的密钥计算 HMAC-SHA1。通过动态截断取得非负整数，再对 `1_000_000` 取模，生成六位验证码。

当前窗口的剩余时间计算方式：

```rust
30 - timestamp % 30
```

### 主要依赖

| 依赖 | 用途 |
| --- | --- |
| `base32` | 解码 Base32 密钥 |
| `sha1` | SHA-1 哈希算法 |
| `hmac` | 带密钥的消息认证计算 |
| `rpassword` | 隐藏输入密钥 |
| `ratatui` | 终端组件与界面渲染 |
| `crossterm` | 跨平台终端键盘事件处理 |

示例界面使用 Ratatui 0.30 系列的 API。新建项目、尚未配置依赖时，可以执行：

```bash
cargo add base32 sha1 hmac rpassword ratatui@0.30 crossterm
```

已有项目应优先保留经过验证的 `Cargo.toml` 和 `Cargo.lock`，避免不必要的依赖升级。

## 安全注意事项

- **密钥比短期验证码更敏感**：持有密钥的人可以持续生成验证码。
- 不要将真实密钥写入源码、README、配置示例、Git 提交、Issue 或日志。
- 不要使用 `cargo run -- <secret>` 传入密钥，避免将其暴露在命令历史和进程参数中。
- 隐藏输入只是不回显字符，并不加密密钥，也不能抵御键盘记录、恶意程序或内存读取。
- 当前代码不主动将密钥保存到文件，但会在内存中保留密钥，且没有实现安全清零。
- 粘贴密钥时注意系统剪贴板历史、跨设备剪贴板同步和剪贴板管理工具。
- OTP 显示在屏幕上，避免录屏、截图或分享终端输出。
- 本工具只生成验证码，不验证验证码，也不负责账户登录或密钥恢复。
- 请妥善保管服务提供的恢复码；不要将本工具作为唯一的账户恢复方式。

## 当前限制

- 一次运行仅支持一个密钥。
- 每次启动都需要重新输入密钥。
- 不支持二维码扫描和 `otpauth://` URI 导入。
- 不支持密钥持久化、加密存储或系统凭据管理器集成。
- 不支持 SHA-256、SHA-512、八位验证码或自定义时间步长。
- 界面会缩放，但过小的终端窗口可能裁剪文字或组件。
- 验证码依赖本机系统时间，无法自动补偿与服务端的时间偏差。

## 常见问题

### 输入密钥时看不到任何字符？

这是正常现象。`rpassword` 默认隐藏输入，输入或粘贴完成后按 Enter 即可。

### 为什么验证码与网站或其他验证器不同？

确认密钥来自同一个账户，检查电脑系统时间是否准确，并确认目标服务使用 HMAC-SHA1、六位验证码和 30 秒时间步长。仅显示相同位数并不代表参数相同。

### 为什么提示 Base32 密钥无效？

标准 Base32 密钥通常使用字母 `A–Z` 和数字 `2–7`。确认输入的不是密码、恢复码、二维码内容或完整的 `otpauth://` 链接。本程序会自动处理空白、小写和 `=`，但不会解析 URI。

### 提示 `new_from_slice` 找不到？

对于当前示例使用的 `hmac` API，在 `src/totp.rs` 中引入提供该方法的 trait：

```rust
use hmac::{Hmac, KeyInit, Mac};
```

不同版本的 trait API 可能不同，应结合编译器提示与项目依赖版本检查。

### 提示 `terminal` 不需要 `mut`？

当前示例使用：

```rust
ratatui::run(|terminal| {
    // ...
})
```

不要额外给闭包参数添加 `mut`。

### 如何退出？

按 `q`、`Q` 或 `Esc`。正常退出时，Ratatui 会恢复终端状态。
